    How shh works

    Facts about the code, which this page cannot test from the inside.

    • Encryption is AES-256-GCM from the browser's built-in Web Crypto. The key comes from 32 random bytes in the link and from the passphrase (PBKDF2, 600,000 rounds).
    • Those bytes are the part of the link after the #. Browsers do not send that part to servers, and this page takes it out of the address bar as it loads.
    • The server stores the ciphertext, padded to hide its length, and a hash proving a reader holds the key. It wipes both after the last open, when the sender destroys the secret, or within a minute of expiry.
    • Five wrong passphrases destroy the secret.
    • Until the link would have expired, the server keeps whether and when it was opened or destroyed, for the sender. It keeps nothing about the reader.
    • shh's server writes no request logs. A proxy or CDN in front of it may keep its own.
    • The book animation runs in a worker with no network access and is never given the secret, the link or the passphrase.

    This page cannot prove that whoever served it left it unchanged: an altered copy could show these same checks. To check, compare this site with the public source. To avoid loading code from a server at all, use the command line client.
